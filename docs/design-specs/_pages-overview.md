# 个人主页页面规划总览（v3：滑动封面 + Tab 详情）

## 1. 项目目标

- 项目类型：公开可访问的个人品牌网站
- 核心目标：在 30 秒内让访客快速理解“你是谁、做过什么、为什么值得进一步联系”
- 主要受众：
  - 招聘方 / 用人经理
  - 潜在合作方 / 创业团队
  - 同行 / AI 产品从业者
- 主转化动作：
  - 被首页吸引 → 点进作品 Tab 看案例
  - 发起联系
  - 下载简历

## 2. 核心架构决策

首页是一本**可以上下滑动的“个人 zine / 幻灯片封面”**，用 7 个整屏章节把全站信息讲完；
所有需要细读的深度内容由**独立 Tab 页面**承载，首页只负责“种草 + 导航”。

```text
摘要层（首页 /）：整屏滑动，7 chapters，每屏一个观点，全部为高信号摘要
   │  每章都有「查看详情 →」入口进入对应 Tab
   ▼
详情层（Tabs）：正常滚动页面，承载完整叙事与可检视证据
```

设计理由：

- 首屏体验即品牌：滑动浏览节奏强、记忆点足，和新粗野主义“翻杂志 / 贴纸 zine”气质一致
- 摘要与长文分离：招聘方 6-11 秒扫描期在首页即可获得完整印象；想深挖的人再进 Tab
- 首页内容严格控量（每屏不允许内部滚动），倒逼信息做减法
- 深度内容有独立 URL，利于分享、SEO 与面试投递

## 3. 视觉风格

- 新粗野主义 Neo-Brutalism（克制版）
  - 视觉签名：2-4px 纯黑描边、零模糊硬偏移阴影、高饱和平涂色块、超粗字体、按压式干脆交互
  - 主色板：墨黑 `#000000`、纸底 `#F4F1EA`、品牌黄 `#FFD400`、电光蓝 `#2F6BFF`、荧光绿 `#3DDC84`、亮粉 `#FF6BB5`
  - 滑动首页像翻一本 zine：每章一种平涂底色（纸底 / 白 / 黄 / 蓝 / 绿 / 粉 / 黑），章节间用 3px 黑实线分隔
  - 原则：有态度但不牺牲可读性，每屏饱和色不超过 2-3 种

## 4. 路由结构

```text
/                       首页：整屏滑动封面（7 chapters，摘要层）
├── C0 COVER            定位封面
├── C1 WORK TEASER      精选作品速览        → /work
├── C2 APPROACH         工作方式速览        →（证据指针跳 /work）
├── C3 PROOF            指标 + 产物速览      → /path#artifacts
├── C4 PATH             履历一行流          → /path
├── C5 ABOUT            人的侧写            → /about
└── C6 CONTACT          黑底尾屏 CTA        → /contact（或直接展开联系方式）

/work                   作品列表（3 个精选 + 更多）
/projects/:slug         项目案例详情（倒金字塔 + AI PM 四要素）
/path                   履历详情（完整经历 + 教育 + 指标 + 产物架 + 简历下载）
/about                  关于（长文自我介绍 + 摄影画廊 + 兴趣）
/contact                联系（邮箱 / 社媒 / 微信 / 简历）
```

## 5. 页面间交互关系

- 顶部导航为跨页面 Tab：首页 / 作品 / 履历 / 关于 / 联系 + 右侧「下载简历」粗边按钮
- 首页内：
  - 右侧固定章节指示点（dots，带章节名 tooltip），点击或键盘 ↑↓ 切屏
  - 鼠标滚轮 / 触控板 / 触摸滑动由浏览器原生接管（CSS scroll-snap，禁止 JS 劫持滚动）
  - 每章右下角「查看详情 →」跳对应 Tab
- Tab 页为普通滚动页，左上有返回首页入口；面包屑层级不超过 1 级
- 首页 C1 项目迷你卡点击 → `/projects/:slug`
- 首页 C3 产物贴纸点击 → `/path#artifacts`
- 简历按钮全站常驻，可下载 PDF

## 6. 首页滑动机制约束（摘要层）

- 桌面端（≥1024px 且视口高度 ≥640px）：纵向 `scroll-snap-type: y mandatory`，每章 `h-[100svh]` + `scroll-snap-align: start`
- 移动端 / 矮屏：关闭 mandatory snap（降级为 `none` 或 `proximity`），章节 `min-h-[100svh]` 自然增长，允许正常长滚动；隐藏右侧 dots
- 每章内容必须在一屏内完整呈现，禁止章节内部滚动；文案超量时删减，不允许加滚动条
- 必须提供：章节 dots、首屏下滑提示、键盘 ↑↓ / PageDown 导航、`prefers-reduced-motion` 降级
- 使用 `100svh`（避免 iOS 地址栏遮挡）；全部章节内容常驻 DOM，保证 SEO 可索引
- 不使用 fullPage.js 一类 JS 劫持方案；仅用极轻量 IntersectionObserver 同步 dots 高亮

## 7. 内容组织原则

- 摘要层只回答“是谁 / 信什么 / 做过什么 / 怎么联系”，不承载长文
- AI 项目案例必须覆盖 AI PM 高信号四要素：
  - 具体用户问题（带数据）
  - 模型 / Agent 方案决策与取舍
  - 效果如何评估（evals）
  - 最终产出、结果与反思
- 指标必须真实；无可靠数字则用成果短句，禁止编造
- 产物（PRD / 评测集 / 看板等）全部脱敏

## 8. 上线建议

- 第一版：首页 7 章 + `/work` 列表 + 至少 1 个 `/projects/:slug` + `/path` + `/about` + `/contact`
- 移动端必须先验证滑动降级与每屏内容不溢出
- 第二版：补齐 3 个案例详情、英文版、摄影画廊
